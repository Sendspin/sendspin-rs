## Goal

Preserve configuration/media ordering without making clear/end/volume wait for decoding, output creation, network acknowledgements, or buffered playback. Keep roles independent. The library, not each application, owns stale-work rejection, invalidation coordination and connection shutdown fencing.

Applications must not compare counters, advance invalidation floors, extract integers from work tokens, or reproduce a locking algorithm from an example. Distinct native Rust newtypes prevent confusing stream invalidation with local playback resets.

## Evidence / scope

Current `src/protocol/client.rs` splits role binary data from stream/control messages. SyncedPlayer enqueue and clear use PlaybackQueue's mutex, but a decode finishing after clear can enqueue stale data. The player example performs synchronous decoding and awaits format requests in its select loop.

`../spec/roles/player/v1.md:96–102` requires preserving buffered chunks across format changes, decoding each in its receipt-time format, and clearing pre-clear chunks only. `../spec/messaging.md:407–430` distinguishes clear (continue stream) from end (inactive, stop output/clear unless role exception). `../sendspin-cpp/src/player_role.cpp:440–503` and `src/sync_task.cpp:792–839` demonstrate independent urgent control plus exact ordered boundaries.

Keep wire schemas, codecs, scheduling/correction algorithms, negotiation and manager policy. A small library-owned session coordinator is now in scope; putting correctness solely in an example is explicitly superseded.

## Implementation Summary / separation of concerns

- Existing router remains the single parser/dispatcher; no decoding, device calls, awaited media sends, or playback mutex acquisition there.
- Private role channels carry ordered configuration/data/markers plus independent latest-state notifications. Public role endpoints encapsulate these channels rather than exposing generation-bearing watch snapshots.
- A library-owned role session/control driver consumes urgent notifications and owns the shared invalidation/terminal fence. It applies output invalidation independently of preparation.
- The application or built-in worker prepares individual items in order; opaque work items commit through the session, never by supplying a counter.
- The cpal output stays on its dedicated owning thread. A device-independent output handle participates in session commits/control. Neither routing nor application code owns the generation algorithm.

## Internal types and invariants

Add crate-private `StreamGeneration(u64)` in a small shared internal module, and crate-private `PlaybackResetGeneration(u64)` in dependency-free src/generation.rs; only playback queue/correction code uses the latter. Both have private fields, no Deref, no From<u64>/Into<u64>, no cross-type conversions/comparisons. Arithmetic is through type-specific internal methods only. Stream generation checked advancement fails closed on exhaustion. Playback reset retains existing wrapping behavior through its own method. Do not derive Default/Copy on public work permits; no public generation accessor/re-export.

Rename existing PlaybackQueue.generation and corresponding correction-state/log locals to playback_reset_generation using symbol-aware rename when available. It advances on queue reset and tells correction/startup state to reset. StreamGeneration advances only on targeted clear/end, not configuration-only Start. It identifies obsolete queued/in-flight work. They are not interchangeable even when values happen to match.

Session identity is independently tracked by Arc identity; a token from session A cannot commit into session B, even when counters match. No public constructible numeric tokens. Terminal closure is a separate boolean fence: transport loss does not invent a protocol generation/End.

Both ordered boundary handling and urgent notification use the same session operation under its mutex: floor=max(floor,boundary). Advancing floor invalidates output; equal/older is a no-op. Ordered markers update this same state even before output exists. Installation applies current floor before publishing a new handle. Commit holds session lock through checked output insertion; lock order session→queue, never reversed. Closure sets terminal closed under that lock, clears output, rejects all later install/commit including equal-generation work. No await, decoding or device creation under these locks.

## Public API / library-owned coordination

Add public role endpoints `PlayerReceiver`, `ArtworkReceiver`, `VisualizerReceiver` returned on Connection and ManagedConnection (`player`, `artwork`, `visualizer` replacing raw audio/artwork/visualizer). `messages` remains for other parsed envelopes. No opt-in mode.

Each endpoint is an ownership-bearing, non-Clone receiver. Attach it once to an output to create a role session. Specify concrete player API in `src/audio/player_session.rs`:

- `PlayerReceiver::attach(output: O, initial_controls: AppliedControls) -> PlayerSession<O>` where O implements a small public `PlayerOutput` trait. Attachment starts one library urgent-control driver on the current Tokio runtime; document the runtime requirement. Output is a cloneable Send+Sync device-independent handle, never cpal::Stream. Callbacks are synchronous, short, nonblocking, serialized, and nonreentrant.
- `PlayerSession::recv(&mut self) -> Option<PlayerEvent>` delivers ordered configuration, audio work, and clear/end notifications. It internally applies markers, skips stale data, and preserves required configuration history. It never awaits expensive preparation. Cancellation of recv must not lose an event; do not dequeue then await within recv.
- `PlayerEvent::Start(StreamPlayerConfig)`, `Audio(AudioWork)`, `Clear`, `End`. `AudioWork` has read-only timestamp/encoded-payload access and consumes itself with `commit(prepared: AudioBuffer) -> Result<(), CommitRejected>`. It captures its issuing session and generation privately. Commit rejection distinguishes obsolete/closed; no integer or alternative-session argument. Work remains valid across format-only Start but not clear/end/close.
- PlayerSession Drop closes the session and stops its control driver; outstanding work retains rejection-only closed state, not authority to keep playback alive. Explicit async shutdown closes first, then joins the driver without waiting for application decode work. Driver holds shared state, not the session object, avoiding an Arc self-cycle.
- Public `PlayerOutput: Clone + Send + Sync + 'static` has synchronous `commit(&self, AudioBuffer)`, `clear(&self)`, `set_volume(&self,u8)`, `set_mute(&self,bool)`, `set_static_delay(&self,u16)`, ALL returning Result<(), OutputError>. No generation parameters. Calls are serialized, short/nonblocking/nonreentrant. OutputError is Clone/Debug with Failed(String) and FormatMismatch{expected: AudioFormat, actual: AudioFormat}; any Failed error (or any clear/setter/end error) terminally fences session, preserves original error, attempts role cleanup once (no recursive retry), drops stored output handle and rejects further work/install. FormatMismatch from commit alone rejects that item and leaves session Open; built-in comparison uses only sample_rate/channels of normalized i32 samples, NOT codec/header/bit_depth. Failed commit must not admit data; cleanup after a failing clear is best effort, never claim hardware stopped. CommitRejected includes Obsolete, Closed, Output(OutputError). Session.status() returns watch::Receiver<SessionStatus> (Open, Closed, Failed(OutputError)), available without recv polling; first failure retained. No final event requirement: terminal recv immediately None. PlaybackControl adapter validates format and surfaces existing callback last_error on operations, with no autonomous cpal-error monitoring promise. Fake outputs test commit/clear/setter/cleanup failure, no retry/spin.
- Add PlaybackControl {queue Arc, GainControl, delay Arc, last_error Arc, AudioFormat}, obtained via SyncedPlayer::control(). Its calls are synchronous and short; cloning the handle is cheap. Existing enqueue/clear/setters share internal helpers; defer logs until session serialization is released. For lazy output, PlayerReceiver::attach_lazy(self, initial_controls: AppliedControls) -> LazyPlayerSession, a public opaque wrapper delegating recv/controls/status/shutdown and begin_output_install to its private slot session; slot is not publicly nameable or constructible. session.begin_output_install() -> Result<OutputInstall, InstallRejected>; permit is Send+'static, non-Clone and reserved once; Drop abandons reservation allowing retry. permit.install(PlaybackControl) consumes it; only a failure while applying controls or terminal closure makes installation unavailable; reservation and already-installed errors do not. On success replay latest controls and apply current invalidation before publication; original stale AudioWork still rejects. Duplicate install returns AlreadyInstalled. No public free-standing slot setter or session bypass. Test clear/end/start spanning creation, abandoned retry, duplicate install and closed install.

For artwork/visualizer use explicit traits: ArtworkOutput: Clone+Send+Sync+'static { type Prepared: Send+'static; commit(&self, channel:u8, prepared:Self::Prepared)->Result<(),OutputError>; end(&self)->Result<(),OutputError> }; VisualizerOutput has same bounds/Prepared and commit(prepared), clear(), end(), all Result. Their attach returns ArtworkSession<O>/VisualizerSession<O>, async recv yields ArtworkEvent<O::Prepared>/VisualizerEvent<O::Prepared>, and data work is ArtworkWork<P>/VisualizerWork<P> whose consuming commit(P) captures erased session output (Send+'static, no Prepared:Clone). Player AudioWork is non-generic Send+'static with erased output capability. Internal coordinator invokes boundary output action at most once when its floor advances: Player End calls clear, Artwork End calls end, Visualizer Clear/End corresponding methods. Delayed ordered marker is informational and never repeats output action after restart. Artwork work exposes read-only is_clear/channel/payload metadata; empty payload remains ordered data, not stream invalidation. Raw decoded UI data publication outside commit is outside session guarantee. Test urgent End/new Start+commit/delayed marker on custom roles.

These explicit output methods let the library clear output and atomically admit work without knowing custom hardware/UI details. They are not a generic role-trait framework: three explicit role traits and shared coordination, with no dynamic role registration. Raw wire Message/chunk parsers remain public for diagnostics; consuming raw bytes outside the session is explicitly outside its playback guarantees. Session APIs must not expose an easy checked-path bypass via raw enqueue examples.

Attachment reconciles retained boundary/command snapshots and producer-closed state synchronously under coordinator serialization before returning; if closed, terminal session admits nothing and clears attached output. recv is async and reconciles latest urgent snapshots before issuing work; while waiting, select shutdown versus data, with no dequeue-then-await. Terminal recv discards queued playback events and immediately returns None (fused thereafter), not a trailing configuration drain. End alone is not terminal; later Start works. Add attach_after_clear_before_driver_poll, attach_after_commands, attach_after_producer_close, closed_session_recv_does_not_drain_playback tests.

### Lazy output and command reporting

One built-in output per player session/connection, created on first decodable audio on a dedicated worker thread. Keep output open emitting silence after End, matching current clear behavior. Codec-only Start swaps decoder, preserves output and buffered audio. Advertise one rate/channels; reject/log mismatched input rather than silently enqueue wrong-format samples. No seamless format conversion added.

Command state internally merges only the field named by current PlayerCommandType; missing required value/Unknown leaves state unchanged and envelope goes to messages. Valid recognized commands apply via library driver independently of work. Volume never changes mute. session.controls() returns watch::Receiver<AppliedControls> with volume:u8, muted:bool, static_delay_ms:u16 (Clone/Debug/PartialEq); initial controls are explicit attach arguments (change receiver.attach signature to attach(output, initial_controls)), replayed before any work. Driver publishes only after successful adapter application. One serial latest-state reporter in example sends current ClientState/PlayerState and doesn't block control. No task per command. Reporter shutdown select cancels waiting on stalled network ack.

## Routing / receiving contract

Private `src/protocol/routing.rs` owns ReceiveSinks/counters and unit tests, constructed by drive and passed into message_router. Keep StreamState in client.rs for latest router-observed format gates, updated before dispatch even with dropped destinations.

| Input | Dispatch |
| --- | --- |
| StreamStart | ordered role config, same stream generation; update active snapshot |
| binary | role data privately stamped current generation |
| Clear/End | advance targeted generation; publish urgent state first; enqueue marker second |
| valid player command | merge private control watch only |
| empty/invalid/unknown ServerCommand | messages unchanged, no command mutation |
| ServerTime | internal clock only |
| other parsed Message | messages unchanged |

Clear None targets player+visualizer; explicit artwork Clear is logged and ignored. End None all three. Empty list none, duplicates once, unknown names ignored, no new negotiation gating. Preserve existing debug envelope log. No duplicate consumed envelopes on messages. send_replace retains latest state internally without watchers. Unused endpoint drop disables only its destination, not connection. Sessions consume final state then terminate on producer closure without watch-close spin. Library driver closes session on transport producer loss so outstanding work is rejected; no synthetic protocol End. Standalone raw diagnostic queues may drain; managed playback does not continue after transport loss.

One synchronous router preserves enqueue boundaries across destinations; observing later messages marker proves earlier dispatch, not consumer processing. No cross-role completion barrier. Malformed frames skip/log. Start before/after odd data remains permissively parsed; session preparation validates decoder availability, not router.

## Playback extension

Keep unconditional SyncedPlayer enqueue/clear for non-protocol local usage. Session path uses PlaybackControl only; no public enqueue_for_generation/invalidate_before methods. Private session commit/invalidate own the generation check; existing queue generation becomes PlaybackResetGeneration. Clearing delegates existing queue.clear (correction reset/reanchor/count semantics), commit delegates existing push/count/trace path; logs outside locks. Place internal typed StreamGeneration in shared module, not protocol-specific module or raw integer bridge.

Output clear and commit are serialized under session lock; PlaybackQueue retains its own callback mutex. A decode completing after invalidation is rejected before output.commit. The built-in output slot publishes/install and applies latest gain/delay under same session serialization. External output implementations must not reenter session methods while being called; document lock/reentrancy contract and test fail-safe shutdown without holding application decode locks.

## Risks / decisions

- The coordinator moves into library because expecting callers to compose generations/locks correctly was inconsistent with the requested API. Three small output adapters are deliberate scope growth, not an automatic decoder/device engine.
- Generation newtypes protect distinct concepts at compile time; private constructors and session-bound work protect domains at runtime without exposing phantom lifetime APIs spanning async workers.
- No bounded-media memory policy or 1.0 header/accounting migration. Clear default excludes artwork now; End retains all-role default.
- Keep one output rate/channels, codec-only switches preserve buffers; no resampling/device-format transition engine.
- Callbacks under serialization must be nonblocking/nonreentrant; no guarantees against an arbitrary hostile adapter. Built-in calls contain no decode/device/network waits. Existing hardware samples cannot be retracted.
- Implementation is authorized. Session/API ownership design has been reviewed, including library-driver teardown and lazy output installation.
